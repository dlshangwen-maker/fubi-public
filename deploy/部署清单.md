# 第一次部署：照着做（腾讯云轻量服务器，不装 Docker）

前提（已核实）：服务器 OpenCloudOS 9.4，Python 3.11.6，8080 端口空闲，连不上 GitHub、能连 DeepSeek。
**不要点控制台的"重装系统"**，服务器上有别的程序在运行。

## 第 0 步：在你的 Mac 上拿到安装包
我（Claude）已经打好：`Read Book/dist/fubi-版本号.tar.gz`（约 7.5 MB）。在访达里打开 `Documents/Claude/ Read Book/dist/` 就能看到。

## 第 1 步：把安装包传到服务器
1. 打开腾讯云控制台 → 你的服务器 → 服务器登录 → **免密登录**，打开网页终端。
2. 网页终端顶部或左边有一个**文件夹图标**（文件管理 / 上传），点开，把 `fubi-版本号.tar.gz` 和 `install_server.sh` 拖进去，传到 `/root/`。
   `install_server.sh` 在 `Read Book/deploy/` 文件夹里。
3. 在终端里输入 `ls /root` 回车，确认能看到这两个文件。

## 第 2 步：安装
在网页终端里执行（把文件名换成你实际看到的）：
```
bash /root/install_server.sh /root/fubi-0.3.0-dev.tar.gz
```
成功的样子：最后一行以 `✓ 启动成功` 开头。
失败时它会自动回滚并打印原因，把终端文字发给作者。

## 第 3 步：放行端口
腾讯云控制台 → 你的服务器 → **防火墙** → **添加规则**：协议 TCP，端口 `8080`，来源 `0.0.0.0/0`（或者只填你和试用者的 IP），点确定。

## 第 4 步：打开看看
浏览器访问 `http://<服务器地址>:8080/`，应该看到书架。

## 升级到带账号的版本（第二次部署）
1. 本机重新打包（我已经打好，在 `dist/` 里，文件名里的版本号以实际为准），再上传 `fubi-版本号.tar.gz` 和 `install_server.sh`，覆盖旧的。
2. 执行 `bash /root/install_server.sh /root/fubi-版本号.tar.gz`。**不会覆盖你已经填好的配置**，只会追加新的配置项。
3. 填 163 邮箱的授权码（只在服务器上做，**不要发给任何人**）：
   - 网页登录 163 邮箱 → 设置 → POP3/SMTP/IMAP → 开启 SMTP 服务 → 会给你一个"授权码"，复制。
   - 在网页终端执行 `nano /etc/fubi/fubi.env`，找到 `FUBI_SMTP_PASS=`，在等号后面粘贴授权码，`Control+O` 回车保存，`Control+X` 退出。
   - 执行 `systemctl restart fubi`。
4. 生成邀请码：先在首页用管理员账号登录（管理员邮箱写在 `/etc/fubi/fubi.env` 的 `FUBI_ADMIN_EMAILS=` 里，升级时会自动追加为 `dlshangwen@163.com`），再打开 `http://<服务器地址>:8080/admin`。页面里有"邀请码"一栏，填备注（发放对象）→ 点"生成邀请码"，把码发给朋友。后台不再使用口令；旧的 `FUBI_ADMIN_TOKEN` 这一行已不起作用，可以删掉。
   后台还有"邮件"一栏：填收件邮箱，点"发送测试邮件"，能看到发信是否成功以及失败的真实原因。
5. 朋友用邀请码注册后，就能用邮箱和密码登录；忘记密码会收到邮件验证码。
6. 如果没填授权码：验证码不会发邮件，而是写在日志里，用 `journalctl -u fubi -n 30 --no-pager` 能看到，你可以手动转告。

## 第 5 步：填模型密钥（不要发给任何人，包括聊天窗口）
网页终端没有 nano，用下面的命令往配置文件末尾追加。**每条命令单独复制、单独回车。**

先写密钥。运行后终端会停住等你输入，**粘贴密钥后回车**（粘贴时屏幕上看不到任何字符，这是正常的，为了不让别人看到）：
```
read -s K && echo "FUBI_MODEL_API_KEY=$K" >> /etc/fubi/fubi.env && unset K && echo 已写入
```
再依次写其余四项：
```
echo "FUBI_MODEL_PROVIDER=openai" >> /etc/fubi/fubi.env
echo "FUBI_MODEL_BASE_URL=https://api.deepseek.com" >> /etc/fubi/fubi.env
echo "FUBI_MODEL_NAME=deepseek-flash" >> /etc/fubi/fubi.env
echo "FUBI_MODEL_THINKING=disabled" >> /etc/fubi/fubi.env
```
最后一行关闭 DeepSeek 的"思考模式"：它默认开着，思考的内容也按输出计费，批量生成不需要。

重启并检查：`systemctl restart fubi`，然后在后台"概览"点"检查模型"，应显示"可以用"。

**想开着思考、但用低强度（比默认便宜）**：思考强度只在思考模式开着时才有效，所以要先删掉上面的 `FUBI_MODEL_THINKING=disabled` 那一行，再写强度，最后重启：
```
sed -i '/^FUBI_MODEL_THINKING=/d' /etc/fubi/fubi.env
echo "FUBI_MODEL_EFFORT=low" >> /etc/fubi/fubi.env
systemctl restart fubi
```
想改回完全关闭：`sed -i '/^FUBI_MODEL_EFFORT=/d' /etc/fubi/fubi.env`，再 `echo "FUBI_MODEL_THINKING=disabled" >> /etc/fubi/fubi.env`，重启。

**填错了怎么改**：不要重复追加同一项（systemd 遇到重复项怎么取，我没有核实过）。先删掉旧的那一行再追加，例如删掉模型名：`sed -i '/^FUBI_MODEL_NAME=/d' /etc/fubi/fubi.env`，再重新写一遍。想看现在写了什么（密钥会遮住）：`grep -E '^FUBI_MODEL' /etc/fubi/fubi.env | sed 's/\(KEY=\).*/\1（已隐藏）/'`。

## 日常
- 看状态：`systemctl status fubi`；看日志：`journalctl -u fubi -n 50 --no-pager`
- 重启：`systemctl restart fubi`
- 升级：传新的安装包，同样执行第 2 步的命令（自动保留上一版，起不来会自动回滚）
- 手动回滚：`ln -sfn $(cat /opt/fubi/previous) /opt/fubi/current && systemctl restart fubi`

## 备份与恢复
- 每天 03:30 自动备份（`fubi-backup.timer`）：数据库用 SQLite 在线备份（服务不用停）+ 导入的书，存在 `/var/backups/fubi/`，保留最近 14 份；每份做完会自检，不通过就不留。后台页面有"备份"一栏，显示最近一次是什么时候，超过 30 小时会标红。
- 立刻备份一次：`sudo -u fubi env $(grep -v '^#' /etc/fubi/fubi.env | xargs) FUBI_BACKUP_DIR=/var/backups/fubi python3 /opt/fubi/current/server/backup.py backup`
- 看有哪些备份：`ls -lh /var/backups/fubi`；检查某份能不能用：同上，把最后的 `backup` 换成 `verify /var/backups/fubi/文件名`。
- 恢复（**先停服务**；当前数据不会删，会挪到数据目录下的 `_恢复前_时间/`）：`systemctl stop fubi`，运行同样的命令把 `backup` 换成 `restore /var/backups/fubi/文件名 --yes`，再 `chown -R fubi:fubi /var/lib/fubi && systemctl start fubi`。
- **备份和数据在同一台服务器上**：能防误删和数据库损坏，防不了服务器整个丢失。要防后者，请定期把 `/var/backups/fubi` 下载到你的电脑（腾讯云文件管理器能下载），或开腾讯云轻量服务器的"快照"。

## 日志与告警
- **日志**在 `/var/log/fubi/fubi-日期.log`，每行一条 JSON，按天一个文件，保留 30 天。不含邮箱、密码、请求内容和查询串，网络地址抹去了最后一段。服务器返回"服务器出现错误"时，提示里带一个编号，用它查：`grep 编号 /var/log/fubi/*.log`。实时看：`tail -f /var/log/fubi/fubi-$(date +%F).log`。
- **告警**：`fubi-monitor.timer` 每 2 分钟在服务器本机巡检一次，出问题给管理员邮箱发邮件：服务没响应（连续两次才报）、数据库异常、磁盘剩余低于 15%、备份超过 30 小时没做、10 分钟内出现 5 次以上服务器错误、模型当天额度用到 90%。同一个问题只发一次，持续存在每 6 小时提醒，恢复时再发一封。后台"监控"一栏显示最近一次巡检；超过 10 分钟没更新会标红。
- 验证邮件能收到：`sudo -u fubi env $(grep -v '^#' /etc/fubi/fubi.env | xargs) python3 /opt/fubi/current/server/monitor.py --test`。
- 收件人默认是 `FUBI_ADMIN_EMAILS`；想发给别人，在 `/etc/fubi/fubi.env` 加一行 `FUBI_ALERT_TO=甲@x.com,乙@x.com`，再 `systemctl restart fubi`。
- **整台服务器宕机时本机巡检自己也停了，发不出邮件。** 目前没有做外部拨测（2026-11-03 用户决定：腾讯云云拨测是付费的，测试阶段先不开）。这意味着整机宕机时不会有人主动通知你，要靠读者反馈或你自己打开网站发现。想补上的办法：腾讯云云拨测（付费，新建"端口性能"任务，地址 `<服务器地址>`、端口 `8080`）；或其他免费的外部拨测服务（我没法联网核实它们现在的免费额度和规则，用之前请自己确认）。

## 用户协议与隐私政策
- 正文在 `server/policy.py`。**改了数据处理方式（多收了什么、换了模型服务商、改了保留期）必须同步改这里，并把 `POLICY_VERSION` 改成新日期**：所有人下次登录时会被要求重新同意。
- 登录、注册必须勾选同意，服务端核对版本并记录（`users` 表的同意版本和时间）。老账号第一次登录时同样会被要求同意。
- 隐私政策里写的联系邮箱是 `dlshangwen@163.com`，请确认这个邮箱适合公开给读者。

## 注意
- 现在是 `http://`，没有 HTTPS：登录密码会明文传输。请试用的人**不要用自己常用的密码**。
- 数据在 `/var/lib/fubi`，配置在 `/etc/fubi/fubi.env`。后台只有管理员账号登录后才能打开。
