# 第 2 步：按回抽取索引（人物 / 概念 / 事件）

每回单独处理，可以并行。合并时按回的顺序拼起来（合并脚本：`merge_index.py`）。

---

你在为一个"不剧透"的阅读器建索引。下面是程乙本《红楼梦》第 {N} 回的全文，每段前面有编号（回.段）。

**只根据这一回的原文抽取，不要用你对全书的了解补充任何这一回没写的信息。** 这一点最重要：你知道很多人物后来的事，但索引里只能写这一回书上写了的东西。

请输出一个 JSON 对象，三个键：

## 1. "人物"

这一回里出现的每一个人物（包括只被提到名字、没有出场的；包括神仙、僧道、丫鬟、小厮）。每个人物：

```json
{
  "名": "林黛玉",            // 最通行的全名；只有称呼没有名字的，用书里的称呼（如"冷子兴""门子""那僧"）
  "这回的叫法": ["黛玉", "林姑娘"],   // 这一回原文里实际出现过的所有称呼，逐字照抄
  "首次": "3.2",             // 这一回里第一次出现（含被提及）的段号
  "出场": "3.2",             // 第一次本人出场（不只是被别人提到）的段号；本回没出场就写 ""
  "这回交代的身份": "林如海之女，母亲贾敏新近去世，被外祖母贾母接到荣国府",   // 只写这一回原文交代的，一两句
  "关系": [["贾母", "外祖母"], ["贾宝玉", "表兄"]],   // 这一回原文明确交代的关系
  "这回做了什么": "离家进京，初到荣国府，拜见贾母和众人，与宝玉初见",   // 一两句
  "备注": ""                 // 例如"同名者""此处只是梦中人物""与某人是否同一人原文不明"
}
```

注意：
- 一个人在这一回有多种叫法时，合并成一条，不要拆成几个人。
- 拿不准两个称呼是不是同一个人，分开列，在备注里写明。
- 群体（"众姊妹""丫鬟们"）不列。

## 2. "概念"

这一回里需要解释的词：典故、器物、称谓、官职、地名、宗教、习俗、书中特有的说法（如"通灵宝玉""太虚幻境""护官符"）。每个：

```json
{"词": "护官符", "首次": "4.6", "说明": "地方官为保官位私下抄录的本地权贵名单"}
```

只列确实需要解释的，每回 10～30 个。说明只写通用含义或这一回原文给出的含义。

## 3. "事件"

这一回按顺序发生的事，每件一句话，带段号：

```json
{"段": "1.12", "事": "甄士隐午睡梦见一僧一道谈论石头下凡之事"}
```

只记事实，不评价，不解读寓意。每回 8～20 件。

---

只输出 JSON，不要其他文字。JSON 字符串内部不要用英文双引号，需要引号时用“”。
