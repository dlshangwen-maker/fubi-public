# 第 5 步：伏笔（小说版）

分两步，两个**不同的**模型调用，防止"挑选偏差"。

---

## 5a 盲标候选（只看到当前位置为止）

你在为一个阅读器挑"伏笔"：读者读到某处时，脑子里自然会冒出的、书里还没回答的问题。

先读 `伏笔标准_v1.1.md`（七条标准、类型、措辞要求）。

输入：《红楼梦》第 1 回到第 {N} 回的原文（带段号）。**假设你从没读过这本书**，只根据这些文字挑问题。不要用你对全书的记忆判断"这个问题后面重要"——这正是要避免的。

对每一回，挑出 4～8 个候选问题。每个候选：

```json
{
  "提出": "1.16",
  "问题": "这位僧人对着英莲念的四句诗，是什么意思？",
  "类型": "悬念型",            // 概念型 / 论证型 / 悬念型 / 人物型 / 预言型
  "为什么读者会问": "僧人突然大哭并念出不吉利的诗，甄士隐也觉得奇怪",
  "能怎么猜": ["只是疯话", "在警告英莲会出事"],   // 标准 6：读者凭已读内容能猜什么；不能写出答案
  "提出锚句": "有命无运累及爹娘之物"   // 提出段里引起问题的那句中 6～12 字，原文一字不差、该段内唯一
}
```

措辞要求（标准 4、5）：
- 不带答案方向，不用"关键""重要""注意""将来""后来""命运""结局"等字眼；
- 不提到读者还不知道的人和事；人名只用提出段之前出现过的叫法；
- 问题里用到的每个事实，都必须在提出段（含）之前读到——宁可把提出位置往后挪一段；
- 所有问题语气平静、长短相近（15～30 字）。

---

## 5b 定位回收（知道全书）

你拿到一份候选问题清单。对每个问题，在原文里找**回答它的地方**：

```json
{
  "提出": "1.16",
  "问题": "...",
  "回收": "1.30",          // 前五回内能找到就写段号
  "回收说明": "英莲在元宵节看灯时被人拐走，正应了僧人那句“好防佳节元宵后”。",   // 1～2 句，只写到回收位置为止读者已知的事
  "距离": "同回",           // 同回 / 跨回 / 五回之后 / 书里不直接回答
  "回收锚句": "早成了一堆瓦砾场了",   // 回收段里给出答案的那句中 6～12 字，原文一字不差
  "讨论方向": "",           // 只有“书里不直接回答”的才填
  "备注": ""
}
```

- 回收说明只能写到回收段为止的内容，不能多说后面的事。
- 答案在第五回之后的：`回收` 写 `"后文"`，`回收说明` 留空，`距离` 写 `"五回之后"`。（前五回 demo 里这类伏笔不会回收。）
- 书里不直接回答的：`回收` 写 `"无"`，`距离` 写 `"书里不直接回答"`，`回收说明` 留空，讨论方向写进 `讨论方向`，只用读者到那时已读的内容。

---

## 5c 筛选（按标准，自动 + 人工）

从候选里选出最终的伏笔：

1. 每回 1～3 处；同一段最多一处。
2. 第 1 回必须有一处同回内回收的短距离伏笔。
3. 书里不直接回答的占 20%～30%。
4. 第五回判词：作为预言型伏笔，选一两首有代表性的即可，不要每首都标（会扎堆，也会让读者以为"每首都要对号入座"）。
5. 去掉不满足七条标准的。
6. 跑一遍 `伏笔标准_v1.1.md` 第六节的自动检查（脚本项 + 四个模型检查：前提、回收、揭晓说明、猜法），不通过的改或删，记进审阅记录。
