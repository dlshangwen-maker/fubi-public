# 解释卡片生成规范（《逻辑哲学论》）

你在为一个手机阅读器预先写解释卡片。读者第一次读这本书，用的是贺绍甲中译本。读者点开第 N 条命题时，他刚好读完第 N 条，没有读过 N 之后的任何内容。

## 每条命题写三档

- **入门**：给完全没学过哲学和逻辑的普通人。用生活里的例子和大白话，少用术语；必须用的术语要顺手解释。
- **标准**：给受过大学教育、愿意动脑的读者。准确、清楚，可以用书里的术语。
- **深入**：给有哲学或逻辑背景的读者。可以讲论证结构、与弗雷格/罗素的关系、德文原词（如 Sachverhalt、Tatsache）、英译与中译的差异、解读上的难点。

## 每档三个字段

- `白话`：一句话，用读者这一档能懂的话重说这条命题在说什么。不超过 50 字。
- `展开`：2–4 句。为什么作者这么说，它和前面读过的哪几条有关，一个例子或类比。不超过 160 字（深入档可到 220 字）。
- `前置`：读懂这条需要先知道的背景知识（通用知识，不依赖本书后文）。不需要就写空字符串 ""。不超过 100 字。

## 不剧透（硬规则）

1. 只能引用编号 ≤ N 的命题。不得出现任何大于 N 的命题编号。
2. 不得预告作者后面的结论、概念或论证，不得说"后面会讲到""这为后文……铺路""这一点在第 X 部分很重要"之类的话。
3. 不得提及作者后期思想（《哲学研究》等）或后人对本书的评价、流派解读（维也纳学派、逻辑实证主义、"坚决读法"等）。
4. 通用背景可以讲：逻辑学和哲学史的通用概念、弗雷格和罗素的工作、作者写书前的思想来源、一战等历史背景。判断标准：这个知识是否依赖本书后文？不依赖就可以讲。
5. 不要写"抓手"式的暗示，不要提出读者没问、却通向后文的问题。
6. 前言和命题 1 的作者原注读者已读过，可以引用。

## 质量要求

- 准确第一：不要曲解原文。拿不准的地方宁可少说。
- 三档要真的不同，不是同一段话换几个词。入门档要让普通人真的能懂。
- 引用其他命题时写编号，如"呼应 2.012"。
- 遇到含公式图的命题（文本里标为 [公式图]），根据英译对照理解公式内容来解释。
- 非常短、只是过渡的命题，白话和展开可以短一些，但仍然三档都写。

## 输出格式

一个 JSON 对象，键是命题编号（字符串），值是：

```json
{
  "入门": {"白话": "...", "展开": "...", "前置": ""},
  "标准": {"白话": "...", "展开": "...", "前置": "..."},
  "深入": {"白话": "...", "展开": "...", "前置": "..."}
}
```

JSON 里的字符串内部不要使用英文双引号 "，需要引号时用中文引号“”或「」。
